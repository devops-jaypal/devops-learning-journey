demo ---> group name (on nodes that are in group)
all ----> on all nodes

MODULES:-

   A module in Ansible is a pre-defined unit of code (like a small program) that performs a specific task on managed nodes.

syntax:- { ansible <group> -m <module_name> -a "<arguments>" }

1.ansible demo -b -m yum -a "name=httpd state=present" -------------> to install a package
2.ansible demo -b -m yum -a "name=httpd state=absent" --------------> to remove the package
3.ansible demo -b -m service -a "name=httpd state=started" ---------> to start the service
4.ansible demo -b -m service -a "name=httpd state=stopped" ---------> to stop a service
5.ansible demo -b -m copy -a "src=/root/file/ dest=/tmp/file" ------> to copy the file
6.ansible demo -b -m user -a "name=mayur state=present" ------------> to create a user
7.ansible demo -b -m user -a "name=mayur state absent" -------------> to remove the user
8.ansible all -m ping ----------------------------------------------> to ping all the servers 
9. ansible demo -m setup -------------------------------------------> to get all the info about the node
10.ansible demo -m setup -a "filter=*ipv4*" ------------------------> to get only the ipv4 address info

HANDLERS:-
 
1.Handlers are special tasks in Ansible that run only when notified by another task. 
2.Handlers are like event-driven tasks — they execute only if something changes in the system.

1.handlers.yml

---
- name: Install and Start Apache using Handlers
  hosts: demo
  user: ubuntu
  become: yes
  connection: ssh

  tasks:
    - name: Install Apache package
      yum:
        name: httpd
        state: present
      notify: Restart Apache    #Triggers the handler only if this task changes

    - name: Copy index.html file
      copy:
        src: index.html
        dest: /var/www/html/index.html
      notify: Restart Apache    #This also triggers the same handler

  handlers:
    - name: Restart Apache
      service:
        name: httpd
        state: restarted

2.ansible-playbook handlers.yml

LOOPS:-
  
1.A loop allows you to repeat a task multiple times with different values — instead of writing the same task again and again.
2.So rather than writing 5 install tasks for 5 packages, you can loop through a list using one clean task.
  
INSTALLING MULTIPLE-PACKAGES

1.loop.yml

---
- name: Install multiple packages using loop
  hosts: demo
  user: ubuntu
  become: yes
  connection: ssh

  tasks:
    - name: Install packages
      yum:
        name: "{{ item }}"
        state: present
      loop:
        - httpd
        - vim
        - git

ROLES:-
 
1.Roles are a way to automatically load related vars, files, tasks, templates, and handlers based on a known file structure.
2.A role is like a folder structure that keeps all the things (tasks, variables, templates, handlers, etc.) for one function — separated and reusable.

Roles-Structure:-

roles/
└── webserver/
    ├── tasks/
    │   └── main.yml
    ├── handlers/
    │   └── main.yml
    ├── templates/
    │   └── index.html.j2
    ├── files/
    │   └── httpd.conf
    ├── vars/
    │   └── main.yml
    ├── defaults/
    │   └── main.yml
    └── meta/
        └── main.yml

Install package tree to see the role-structure:-
yum install tree -y

tasks -------------> Contains the main tasks, like installing packages or starting services.
handlers ----------> Contains handlers that are triggered by tasks (for example, restarting httpd after installation).
templates ---------> Contains Jinja2 template files that can be dynamically customized before deployment.
files -------------> Contains static files that will be copied directly to target systems.
vars --------------> Contains variables that are specific to this particular role.
defaults ----------> Contains default variables for the role (these have the lowest priority).
meta --------------> Defines metadata about the role, including dependencies on other roles.
